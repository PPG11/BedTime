# BedTime 开发与验证

## 定位改动

- 从仓库根目录的 `AGENTS.md` 开始。依赖、构建和模拟器操作见 `docs/local-development.md`。涉及云函数、集合或环境时，读 `docs/cloud-deployment.md` 和 `cloudfunctions/README.md` 的相关章节。
- 从页面的操作入口追到 `src/services/` 和 `cloudfunctions/`，对照当前请求、响应及数据库字段。打卡主流程按日写入，兼容路径保留旧的按用户汇总记录。涉及日期、权限或去重时，检查两条路径及已有数据。
- 按需求区分投稿、回赠和打卡。原有实现由打卡触发抽取，投稿成功只更新投稿状态。若任务要实现「送出后收到」，验证回赠归属与持久化，以及失败重试后是否仍显示同一条。

## 按改动选择验证

1. 用 `yarn build:weapp` 构建。修改云函数时，本地执行受影响的处理器或模拟数据库请求，覆盖正常路径和失败重试。把本地验证与微信端联调分别记录。
2. 改动日期或打卡规则时，用目标 22:30 检查午夜前后及 04:30 窗口边界，再覆盖目标在 00:00 后的情况。核对提交、首页恢复、历史统计和关联心语使用相同的周期日期。
3. 改动心语、好友或权限时，用两个测试账号验证对应流程。心语覆盖空池、排除本人和重进后的回赠一致性。好友覆盖申请、接受、删除后重进。权限覆盖普通用户跨账号读写失败，响应只包含业务需要的字段。
4. 改动持久化时，按影响范围验证重复点击、客户端超时后重试和部分写入失败，核对记录、计数和关联 ID。

## 云端操作

- `yarn cloud:preview <函数名>` 用于核对上传范围。改到 `cloudfunctions/common/` 时，核对受影响的函数依赖。部署预览和构建结果只证明本地检查。
- 实际上传、修改云数据库、安装触发器或发布体验版均按用户授权的范围执行。执行前核对环境 ID、AppID 和函数名单；联调使用指定的测试环境与测试账号。
