# BedTime 开发与验证

## 定位改动

- 从根目录 [AGENTS.md](../../../AGENTS.md) 和 [架构说明](../../../docs/architecture.md) 定位。构建与模拟器见 [本地开发](../../../docs/local-development.md)；涉及云函数与集合时再读 [部署说明](../../../docs/cloud-deployment.md) 和 [接口契约](../../../cloudfunctions/README.md) 的相关部分。
- 沿 `miniprogram/pages/` → `state/app-data.ts` / `services/` → `cloudfunctions/` 追踪操作。状态实现放在可注入依赖的 `state/create-app-store.ts`；前端业务调用在 `services/cloud.ts`，服务端身份和错误处理在 `cloudfunctions/common/response.js`。前端使用原生 Page、TypeScript、WXML、WXSS，构建产物在 `dist/`。不要恢复 Taro / React 接口或直接修改产物。
- 页面视图数据应可序列化；定时器、订阅和请求上下文留在逻辑层。修改异步页面时核对隐藏 / 卸载清理，以及旧用户、旧周期响应不会覆盖新状态。
- 打卡按周期日写入。由服务端计算窗口、状态和奖励；同一事务保存记录与统计，重试返回原记录。只有 `hit` 延续连续，`late` 仍计累计；当前连续和累计用服务端摘要，近期最佳限于已加载的最近 365 次记录。
- 区分投稿、回赠和打卡。当前抽取由打卡触发，投稿成功只更新投稿状态；「送出后收到」需单独实现回赠归属、持久化和重试一致性。现有后端边界集中记录在 [业务链路](../../../docs/checkin-and-friends-backend.md)。

## 按改动选择验证

1. 以 `yarn verify` 执行类型检查、测试和构建。新增测试覆盖可观察行为与业务边界，不通过匹配实现文本证明功能。云函数改动还应本地执行受影响处理器或模拟数据库请求。
2. 日期变更对照服务端 `resolveCycle` 与前端 `resolveCheckInCycle`。目标 22:30 覆盖午夜、04:29 与 04:30；窗口结束不包含在可打卡区间。目标 00:30 覆盖前夜 23:30，核对提交、首页恢复、统计和心语都采用同一周期。统计变更还覆盖迟到、漏过完整周期、当前周期未打卡及超过历史加载上限，避免旧连续值长期保留或累计被截断。
3. 心语、好友或权限变更在获准写入的测试环境用两个账号联调。心语覆盖空池、排除本人、重复投稿和重进后奖励；好友覆盖申请、接受 / 拒绝、分页、解除与重进；权限覆盖跨账号读写失败及最少返回字段。
4. 持久化变更检查重复点击、客户端超时后重试和部分写入失败，核对记录、计数和关联 ID。不能用页面按钮防重替代云端幂等。
5. 原生页面变更必须在微信模拟器查看实际布局，覆盖窄屏及受影响的有数据 / 长文本状态；样例数据只证明展示效果。优先核对 v2 按钮选择器优先级、默认宽度与外边距、控件 `border-box` 和 `px` 屏幕断点，详见[原生布局检查](../../../docs/local-development.md#原生布局检查)。`wcc` / `wcsc` 通过只证明可编译。输入、滚动、弹层、Picker 和分享仍需真机确认；分别记录模拟器、真机、云端联调与部署结果。

## 云端操作

- 构建与部署共用 `scripts/cloud-env.cjs`，终端的 `CLOUD_ENV_ID` 优先于 `.env.local`，没有默认环境或旧别名。缺少环境会使构建失败；仅显式 `ENABLE_CLOUD=false` 用于离线预览。监听会响应 `.env.local` 修改，终端环境变量变化需重启任务。小程序上传前运行 `yarn build:release`，不能以离线产物发布。
- `yarn cloud:preview <函数名>` 核对上传范围。四个业务函数依赖 `cloudfunctions/common/`；改动共享模块时检查受影响函数。使用官方 `wechatide.cloud_fn_deploy` 前，执行 `yarn cloud:prepare <函数名>` 准备当前依赖：它不上传、不读写部署缓存，也不需要微信 CLI；脚本上传则自动准备依赖。缺少必需依赖会停止，不要直接上传遗留 `node_modules/`。预览、构建和依赖准备仅证明本地结果，工具待确认也不能记作部署成功。
- 实际上传、修改云数据库、安装触发器或发布体验版均按用户授权的范围执行。执行前核对环境 ID、AppID 和函数名单；联调使用指定的测试环境与测试账号。
