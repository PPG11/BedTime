# Taro → 微信原生迁移

> 历史记录：以下描述旧产品；2026-11-08 已移除旧前端与业务规则，四个旧领域函数已改为停用入口。当前实现见 [M1 交付记录](refactor-m1-delivery.md)。
本文记录原生前端迁移范围与历史验证，当前业务和云端契约以 [业务链路](checkin-and-friends-backend.md) 和 [云函数说明](../cloudfunctions/README.md) 为准。

开发基线已调整为微信原生小程序 + TypeScript + CloudBase，后续前端开发在 `miniprogram/` 进行。最初的前端迁移沿用旧云端；后续已改为四个业务云函数与每日打卡文档，旧代理接口、旧汇总打卡和旧定时任务不再属于当前代码架构。

## 迁移对应

| 原实现 | 原生实现 |
| --- | --- |
| Taro / React 应用入口 | `miniprogram/app.ts` 中的 `App` |
| `src/app.config.ts` 与页面配置 | 原生 `app.json`、页面 `index.json` |
| React 页面和展示组件 | 页面 WXML、事件方法和 WXSS |
| React Context / Hooks | `state/app-data.ts` 订阅状态与页面逻辑模块 |
| `Taro.cloud`、存储、剪贴板、提示与分享 | 原生 `wx` API 与页面分享生命周期 |
| Webpack / Babel / Taro 构建 | TypeScript 编译 + 原生资源复制 |
| `src/services/`、`src/utils/` | 迁入 `miniprogram/`，对接当前业务云函数与本地存储 |
| `TARO_APP_CLOUD_ENV_ID` | 改用 `CLOUD_ENV_ID`；旧别名与默认环境已移除 |
| H5 和其他小程序平台脚本 | 移除，后续以微信小程序为目标 |
| 默认未启用的有数示例 SDK 与样例 token | 移除；如需分析能力，应另行配置真实接入 |

前端不再有运行时 npm 依赖。开发依赖包括 TypeScript 和微信官方类型声明；云函数的 Node.js 依赖仍单独按工作区维护。`project.config.json` 保留现有 AppID、`dist/` 入口和用户已设置的开发者工具选项。

## 功能核对表

| 页面 / 范围 | 保留的功能 | 主要入口 |
| --- | --- | --- |
| 打卡首页 | 目标时间、窗口状态、打卡、重复提交反馈、统计、近期记录 | `miniprogram/pages/home/` |
| 晚安心语 | 投稿、已投稿恢复、打卡奖励、按消息 ID 恢复、空池处理、点赞 / 点踩 | 首页与 `services/goodnight.ts` |
| 好友 | UID 添加、申请接受 / 拒绝、好友列表、分页、备注、删除 | `miniprogram/pages/friends/` |
| 我的 | 昵称和目标时间编辑、UID 展示与复制 | `miniprogram/pages/profile/` |
| 分享 | 原生分享菜单、微信好友与朋友圈分享参数 | `wx.showShareMenu`、页面生命周期与 `utils/share.ts` |
| 数据 | 用户档案、每日打卡与本地好友备注 | 业务云函数、服务层与 `utils/storage.ts` |

迁移同时统一打卡周期计算，覆盖夜间目标跨午夜与凌晨目标在前夜开放的情况。窗口继续采用目标前 12 小时至后 6 小时，结束边界不包含在可打卡区间中。

当前代码已由服务端校验打卡窗口，以事务写入打卡和统计，并持久化心语投票去重。投稿后立即回赠仍未实现；线上是否运行当前版本需独立核验，不能从本地代码推断。[现有边界](checkin-and-friends-backend.md)

## 验证边界

本地检查命令为 `yarn verify`。它覆盖类型检查、自动化测试和小程序产物生成；具体测试用例以 `tests/` 为准。`wcc` / `wcsc` 编译 WXML / WXSS 不会运行页面生命周期、微信 API 或云函数。模板编译、模拟器运行、双账号云端联调、真机行为和发布需分别验证，不能由本地通过推断完成。

前端构建不创建集合、不上传云函数，也不发布体验版或正式版。当前四函数所需集合、索引和权限见云函数说明；旧架构数据如需保留，应另行核对转换方式，不能继续依赖旧 `info[]` 兼容读取。

## 云端重整后的本地修复

构建与部署改为共用 `.env.local` 和终端配置；缺少环境不再静默生成离线版，发布构建拒绝离线配置，部署打包缺少必需依赖时停止。三个页面通过原生 API 开启分享菜单，移除无效页面配置。统计区分按时连续、累计打卡和最近 365 次记录中的最佳连续，口径见业务链路。

当前构建、测试、模拟器与云端验证结果应分别记录，不能沿用上面的初次迁移结果。新环境的配置和在线验收见[云环境与部署](cloud-deployment.md)。

## 微信端核验清单

在已授权的测试环境编译 `dist/` 后检查以下行为：

- 冷启动和切换三个 Tab；加载失败后重试，前后台切换后状态恢复，无重复定时器或重复请求。
- 修改昵称 / 目标时间，首页和我的即时同步，退出重进后保留；昵称失焦保存时检查网络失败提示和重试。
- 对 22:30 目标覆盖窗口开启、目标时刻、午夜、04:29 与 04:30；对 00:30 目标覆盖前夜 23:30。核对按钮状态、周期日期、统计与心语一致。
- 打卡成功、连续点击、已打卡再次进入、网络超时后重试；核对每日云记录、用户摘要和奖励 ID。检查迟到中断连续、漏过周期后的连续归零，以及历史记录超过 365 次时累计和当前连续不被截断。
- 投稿空内容、长度限制、重复投稿和重新进入；空心语池、收到奖励、点赞 / 点踩以及重进后的奖励恢复。
- 两账号完成发送、接受 / 拒绝、分页和解除好友；接受后双方列表同步，备注重进后保留，复制 UID 与分享正常。
- 普通用户跨账号读写失败，云函数响应仅含业务需要的字段。
- 真机检查键盘、输入框、滚动、弹层关闭、Picker、TabBar、安全区和分享入口，记录微信版本、基础库版本与设备。
