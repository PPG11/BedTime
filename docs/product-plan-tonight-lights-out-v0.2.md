# 今晚关灯 · 产品方案 v0.2

2026-11-07 · 设计评审稿

**一个会催你走的小程序。** 每晚打开一扇暖窗，按住关灯，读一句晚安，点「放下手机」离开。想起一个人时，可以把同一扇窗留给对方。对方可以回一盏灯，也可以在自己的时间关灯。

首批用户是已经想休息、还想再刷一会儿手机的人。第一批传播从原本就会互道晚安的朋友、伴侣和室友开始。关灯是用户主动记录「我准备休息了」。个人仪式是否值得每晚重复、留灯是否能变成自然的双向动作，要分开验证。

## 今晚

### 第一次打开

首页直接是一扇亮窗和一句话「准备休息时，来关一次灯。」点选 22:00、22:30、23:00，或自定义一个关灯时间。默认 22:30，可点「先这样，今晚试试」。已有用户直接使用原目标，昵称和好友关系以后再处理。

### 仪式窗口

在现有服务端周期和档案时区上叠加展示区间 **[目标前 3 小时，目标后 6 小时)**。前端只在这个区间显示新的关灯操作。服务端继续接受原有的目标前 12 小时至目标后 6 小时区间，便于旧客户端兼容。

| 目标 | 新界面可关灯的区间 | 边界 |
| --- | --- | --- |
| 22:30 | 当天 19:30 至次日 04:30 前 | 19:30 开窗，次日 04:29 仍属上一晚，04:30 起进入下一周期。 |
| 00:30 | 前一晚 21:30 至当日 06:30 前 | 21:30 开窗，23:30 已属于次日 00:30 的目标周期，06:30 起进入下一周期。 |

窗口未开时展示亮窗和「今晚 19:30 开窗」这类时间提示。窗口内首屏留一扇窗、一句状态和一个主操作，作息目标放在「我的」。过了目标仍可关灯，状态文案可用「晚一点，也可以把今天放下」。旧客户端提前写入了同周期记录时，新版直接恢复完成态。首页、留灯卡入口、重进和记录都用同一个服务端周期。 [现有周期规则](../cloudfunctions/common/time.js) · [业务链路](checkin-and-friends-backend.md)

### 长按关灯

首轮用 **约 800ms** 的按压阈值，在 600–900ms 内用原型试手感。手一按下，窗内暖光就开始收拢。按满之前松手、滑出按钮或切到后台，光恢复，用户可以再试。到阈值只提交一次，按钮变成「正在确认…」。按压过程靠光和灯绳表现进度。

从第一次就提供低强调的「轻点关灯」。它与长按使用同一条提交流程。确认成功后才完成最后一次熄灯，配一次轻震动和一颗星。默认静音，弱动效模式直接切换到静态暗窗。若网络超时，提示「还没确认，再试一次」，先查同周期是否已写入，确认有记录就恢复完成态。按压过程中窗口关闭或目标变更时，先刷新，再由用户决定是否对新周期操作。

### 完成态

全屏夜色。暗窗旁有一颗星，下面直接显示一条晚安签。页面保留一个主操作「放下手机」和一个轻入口「看看夜空」。

```text
       ┌────────┐
       │  暗窗  │  ·
       └────────┘

       今天就到这里。
       剩下的，明天再说。

       来自晚安心语 · 匿名

       [ 放下手机 ]
         看看夜空
```

用户主动点「放下手机」时调用 `wx.exitMiniProgram`。调用失败或客户端不支持时保留完成页，轻提示可用微信右上角退出。收尾时长以进入后台计时，看看夜空的跳转单独记录。重新打开时恢复同一晚的结果。 [微信小程序退出接口](https://github.com/wechat-miniprogram/api-typings/blob/v3.12.3/types/wx/lib.wx.api.d.ts#L22733-L22744)

## 晚安签与夜空

**晚安签** 是关灯后直接看到的一句晚安。服务端先确认打卡，再独立读取或分配一条审核通过的公共心语。为空、超时或内容已下架时，显示标注「今晚关灯」的编辑短句。例如「今天先存个档，明天继续。」完成页始终只呈现一句，页面打开后保持稳定。同周期已分配的签可在夜空回看，刷新不重新抽取。真实心语署名「来自晚安心语 · 匿名」。

**夜空** 首屏是七晚窗格，有记录的夜晚留一颗星。按时和较晚用同一种星，空白窗格表示那一晚没有记录。再往下可以展开三十晚，回看晚安签，或进入私密的「记录详情」。累计、当前连续和近期最佳沿用已有口径，近期最佳的范围标为最近加载的 365 次打卡记录。夜空不显示好友统计。

**投稿** 放在夜空，入口叫「给下一个关灯的人留一句」。每个周期最多成功投稿一条，最多 80 字，不选收件人。提交时显示「正在检查…」。云函数沿用微信 `msgSecCheck` 自动审核，通过才入公共池，可由其他人抽到。未通过提示修改，审核服务暂不可用时保留草稿让用户稍后重试。读签与投稿各自独立，作者可回看自己的投稿。收到的签可在夜空举报，供下架处理。 [现有审核和抽取逻辑](../cloudfunctions/common/goodnight.js)

## 留灯与回灯

留灯是一张用户主动通过微信分享的预设晚安卡。入口放在「一起」和白天可访问的「夜空」。发卡人从三条固定文案里选一句，卡片沿用同一扇暖窗。首个版本用「今天辛苦了，困了就去睡。不用回我。」卡面与链接省略昵称、UID、就寝时间和打卡记录。

接收者点开卡片先读到完整晚安，随后可以任选下面的动作。

- **我也关灯。** 直接在同一扇窗里进入个人仪式。第一次可快速确认目标时间，仪式窗口已开才显示关灯动作。窗口未开时展示自己的开窗时间。
- **回一盏灯。** 打开微信分享面板，用户可以把同款预设窗景发回原聊天。窗口外或已经关过灯也能回灯。点击、生成卡片和调起分享都不记作关灯，自己的首晚记录以主动操作并成功写入为准。
- **先收下。** 读完可以直接离开。卡片过期或撤回后显示通用晚安，并停止关联原卡的来源。

传播靠两个人愿意回赠这张卡。回灯可发生在首次关灯之前或之后，用户自己选顺序。预设卡在微信聊天里流转，匿名心语通过公共池分发，好友关系通过单独的邀请建立。产品内无需增加私信、收件箱、已读或回灯通知。

```text
留灯卡 ───→ 收卡人读到晚安 ───→ 回一盏灯 ───→ 原聊天收到同款窗景
                     │
                     ↓
                主动关自己的灯 ───→ 留下首晚记录
```

## 一起

P1 上线轻量好友窗。首屏先展示称呼和一排窗，再展示「邀请好友」与待处理申请。空状态「一个人关灯，也成立。」这里的陪伴感来自好友各自在今晚关过灯。

- **邀请。** 发出独立的微信好友邀请卡，对方打开后主动点「接受邀请」。已有的 12 位 UID 改称「好友码」，放在「我的」和邀请页的备用入口，保留输码申请。收留灯卡、回灯或首次关灯都不自动添加好友。
- **可见范围。** 复用已有双方确认的好友关系。各自选择是否向已确认好友公开自己的当晚状态，旧关系迁移时默认关闭。开启后，好友看到「已关灯」或「尚无记录」和称呼。关闭时只显示「未共享」。公开的状态按该好友自己的有效周期计算，关闭共享或解除好友后立即停读。
- **页面密度。** 好友窗不显示具体时间、目标、迟到、历史或连胜。列表下方再处理申请与关系管理。没有邀请和好友时，仍可完成个人仪式。 [现有好友关系和字段](../cloudfunctions/common/friends.js)

P2 在轻量「一起」出现第二周复用后，再验证一对一的双人窗。首轮观察重点是用户是否主动回来看同一位朋友，而不是把好友数量当成成功。

## 自愿提醒

「我的」可提供「提醒我一次」，默认关闭，用户主动点后才申请微信订阅授权。首轮测试目标前 10 分钟的一条提醒。例如目标是 22:30，提醒时段为 22:20，文案按实际可用模板配置。已错过提醒时间时，界面显示下一次可选的时间，由用户决定是否预约。

微信一次性模板的一次授权只可发送一条，记住授权选项也不等于每天已授权。首轮核对后台是否有适合的模板和权限，再用真机验证。服务端发送前检查授权、用户开关、目标及周期、当晚是否已有记录，同一周期最多发送一次。用户取消、已关灯、改目标导致原计划失效或周期结束时，取消该次提醒。提醒是独立小流量验证，有合适模板再开放。 [腾讯云订阅消息说明](https://cloud.tencent.com/document/product/1301/103770)

## 视觉和文案

**用一处暖光把窗画成真实的物件。** 窗框、窗台、玻璃反光和一点水汽先建立层次，窗台只选植物或猫的剪影作为识别点。亮窗照到窗台，暗窗留下玻璃反光和一颗星。同一套窗形用于今晚、七晚窗格、好友窗和微信卡面。全天统一夜色，窗口未开用亮窗和文案表达时间。

| 元素 | 设计基准 |
| --- | --- |
| 夜色 | `#080C18` 为主背景，`#111827` 用于必要的次级面。用留白和细线区分层级。 |
| 暖光 | `#F2B36B` 用在窗内和主操作，`#D98B43` 用在暗部，`#F6D49A` 留给星。 |
| 文字 | 暖白 `#F4EFE5`，次级文字先用实色 `#B4AEBA`，按实际背景检查可读性。标题和晚安签优先宋体，正文与操作用系统无衬线。 |
| 手感 | 暖光随按压收拢，确认后短促熄灭，星点出现一次。录一段约 8 秒的演示，能看清亮窗、按压、熄灯和一句晚安。 |
| 尺寸 | 操作区至少 44px，保留微信胶囊和安全区。检查 320px、放大字号、长心语和弱动效。 |

用「先这样，今晚试试」「晚一点，也可以把今天放下」「还没确认，再试一次」这类短句。按时、较晚和漏记留给个人记录，窗景与收尾文案给每个夜晚同样的待遇。

## 衡量与试用

| 指标 | 口径 |
| --- | --- |
| 每周反复关灯的人 | 最近 7 个完整个人周期至少有 3 晚服务端确认记录的独立用户数，同时报告同口径比例。 |
| 首晚和第二周 | 首次打开后 48 小时内至少关灯一次。对观察满两周的首周激活用户，看第 8–14 个周期至少关灯三晚的比例，首轮目标 30%。 |
| 收尾时长 | 从确认成功且展示完成态到小程序进入后台，报告中位数和 90 分位。中位数目标 ≤10 秒。「看看夜空」另记，仍在前台的样本单列，避免只统计离开最快的人。 |
| 留灯传播 | 分开报告打开过有效卡的新访客、48 小时内首晚写入、点回灯、回灯卡的实际打开。调起分享只记动作，不能当作发送成功。首轮至少积累 30 位有效新访客再看转化，试验目标 30%。 |
| 好友回访 | 有状态授权的好友对中，有多少对在不同夜晚反复打开「一起」。同时记录仅看一次和只做个人仪式的人。 |
| 可靠性 | 窗口内有效提交按用户与周期去重后，最终拿到记录的比例，目标 ≥99%。分列失败、超时恢复、跨周期拒绝。 |

小规模试用先观察理解和操作，再看实际行为。单人试用第二周取消研究组织者的主动提醒，熟人试用则区分被布置发卡的任务与后来主动发卡的行为。次日可以请用户回顾关灯后有没有放下手机，单独报告自述。事件只采集完成指标需要的去重标识、版本、动作、状态类别和来源。

## 数据兼容和验收

1. **保留周期与记录。** 个人打卡、服务端统计、用户资料和关系继续复用现有数据。夜空由打卡记录派生。关灯只等待账号和当晚状态，历史按需加载。保留既有首页、好友和资料路由，旧分享可正常进入，新留灯与好友邀请使用不同的入口标识。
2. **关灯写入与晚安签分别完成。** 当前提交会先访问心语池。新版先完成幂等打卡事务，再分配或读取晚安签。沿用历史心语归属，向接收者返回不透明引用，避免通过现有 `uid_date` 标识推回作者。举报下架后已分配的引用也停止返回原文。 [打卡写入](../cloudfunctions/common/checkins.js) · [心语返回结构](../cloudfunctions/common/goodnight.js)
3. **好友服务端执行可见规则。** 复用已有关系与请求去重；邀请卡和留灯卡使用不同用途的短期标识，暂定七天。新版状态查询只返回称呼、可见状态和必要的关系标识。旧接口同时遵守共享设置，避免旧客户端绕开权限。用两个账号验证接受、拒绝、撤销授权、解除和转发。
4. **按功能开关分步切换。** 单人仪式、留灯、一起、提醒分别控制。新旧界面共读原记录，回退后仍能读取新版产生的打卡。改代码后运行 `yarn verify`，在微信模拟器检查窄屏和长内容，在 iOS、Android 真机检查长按、弱动效、退出、卡片冷启动与热启动、过期与转发、自动审核和一次性授权。测试目标 22:30 与 00:30 的开闭边界、同一晚跨午夜、按压跨关闭、改目标、重复点击和超时后恢复。

本轮产品评审优先确认三个体验。按住一扇窗是否比普通按钮更有结束感，用户能不能在完成后顺手离开，以及收到卡片的人会不会自然想回一盏灯。三者分别观察，便于在重构前知道哪一段值得继续投入。
