# 今晚关灯 · 产品方案 v0.3

2026-11-07 · 在 v0.2 上的进一步设计

v0.2 我基本同意，而且有五处比我上一版更成熟。v0.3 不推翻它，只推进几处仍然不够稳的地方：完成页的留灯入口、一起的时间语义与共享同意、回灯的回应感、夜空与晚安签的质感，以及第二个传播引擎。文末列出需要拍板的六件事。

## 一、v0.2 做对了什么（不改）

1. **完成页只留「放下手机」和「看看夜空」。** 我上一版把「留灯」放成完成页的第二个按钮，会让「催你走」变成一句带增长目的的话。v0.2 更干净，这个纯度要保住。
2. **按时和较晚用同一种星。** 删掉视觉上的优劣，比我的亮星/淡星更一致。关灯这一晚只属于这一晚。
3. **留灯与好友邀请是两件事。** 收卡、回灯、首次关灯都不自动加好友。这个边界非常清楚，不能为了增长把它糊掉。
4. **共享状态需要双方同意，旧关系默认关闭。** 比我上一版更尊重隐私。一起的窗不是默认公开的。
5. **提醒独立、谨慎。** 没有把订阅消息当成默认增长手段，也没有在留存数据里混入提醒的干扰。

这五点是产品的骨气，v0.3 不动。

## 二、最大的风险：产品太安静，传播起点太远

v0.2 为了完成页的纯度，把留灯入口放在「一起」和「夜空」。这个取舍是对的，但有一个代价：**完成页是用户最可能想起「想发给谁」的十秒钟；离开之后，他大概率不会再回来找入口。**

这不是要加回一个按钮。按钮会让「放下手机」变成一句带任务的话。v0.3 建议用一种更轻的方式保留这个瞬间，同时承认：**这个产品的传播不一定主要发生在小程序里。**

两个引擎：

- **一对一：留灯卡。** 在微信聊天里流转，负责把一个人带进来。
- **一对多：8 秒演示。** 亮窗、按住、熄灯、一句晚安、手机放下。它负责让不认识的人看见这个动作，是更可能「爆」的那一层。

v0.2 把 8 秒演示写进了视觉规范，但只当成验收素材。v0.3 建议把它提升为独立的传播资产：**先拍一条让人愿意看完的 8 秒，再谈卡片。** 一个会催你走的小程序，最好的广告就是它真的让一个人走了。

## 三、需要推进的地方

### 3.1 完成页：把「留灯」写成一句很轻的话

保留 v0.2 的结构：

```text
        ┌────────┐
        │  暗窗  │  ·
        └────────┘

        今天就到这里。
        剩下的，明天再说。

        今晚关灯

        [   放下手机   ]
          看看夜空
```

这是本地短句的基线形态。如果抽到真实晚安签，只替换这一句，来源改成「来自一位也关灯的人 · 匿名」；版式不变。

在「看看夜空」下方，隔开一段留白，再放一行很小的文字：

```text
        想留给谁，就留一盏灯。  ›
```

不是按钮，不加图标，不做动效，不写「分享给好友」。它是一句脚注，不是第二个主操作。点它才打开留灯面板；不点，什么也不发生。

**为什么是文字而不是按钮。** 完成页的情绪是「结束」，不是「传播」。按钮会抢占视线，文字不会。用户如果正在想某个人，这行字刚好在那里；如果不想，它不会拦路。

**A/B 验证。**

- A：v0.2 的纯完成页。
- B：加这行文字。
- 各 10–15 人，观察留灯面板打开率、完成到退出的时长、访谈里是否觉得「被要求分享」。
- 判断线：如果 B 的留灯面板打开率明显更高，且完成到退出的中位数没有变慢，保留；如果用户觉得被打扰，或退出变慢，删掉。宁可少一个入口，也不要让「放下手机」变成一句假话。

### 3.2 一起：先解决「今晚」的时间语义

v0.2 说好友看到「已关灯」或「尚无记录」。问题是，**「尚无记录」在下午三点看到，像一句审判；在凌晨一点看到，才像事实。** 而且好友的目标可能在 00:30，你们说的「今晚」并不是同一个周期。

服务端不要只返回 `hit / late / miss / pending`，而是按**好友自己的有效周期**算出一个更细的状态：

| 状态 | 文案 | 什么时候出现 |
| --- | --- | --- |
| `not_open` | 窗还没开 | 好友的仪式窗口还没开始 |
| `open_no_record` | 还亮着 | 窗口已开，好友还没关灯 |
| `closed_record` | 已关灯 | 好友今晚有记录 |
| `closed_no_record` | 今晚没有记录 | 好友的窗口已经结束，没有记录 |
| `not_shared` | 未共享 | 好友没有向你公开今晚状态 |

页面只返回 `{ uid, name, state, sameCycle }`，不返回目标时间、具体就寝时间、历史或连续。`sameCycle` 为 false 时，在窗下加一个很小的「TA 的今晚」，不显示日期。这样既回答了「这是哪一晚」，又不把时间变成监控。

不要在页面上写「尚无记录」或「今晚没关」。用「还亮着」「窗还没开」「今晚没有记录」这些中性的状态词。它们描述窗，不评价人。

### 3.3 一起：共享同意要一次问清，不要留一屏「未共享」

v0.2 说旧关系默认关闭，这很对；但新关系没有说默认值。如果新朋友也默认关闭，第一次打开「一起」会看到一排「未共享」，像一屋子关着的门。

建议：

- **新邀请的接受流程是两步。** 第一步「接受邀请」；第二步一个开关：
  > 让 TA 看见我今晚关没关灯
  > 只显示今晚，不显示时间、历史、晚安签。
  > [开] / [关]
  默认开，但用户看得见、可以关。这是被邀请时的一次知情同意，不是默认公开。
- **旧关系保持默认关闭。** 在「一起」顶部放一张一次性提示卡：「你还没向好友公开今晚的灯」+「开启共享」。不要给每位好友显示「未共享」。
- **「我的」里有一个总开关。** 「让好友看见我今晚是否关灯」。关掉后，好友的窗从列表里消失，不留下「未共享」的痕迹。
- **部分好友没共享时，不逐行展示「未共享」。** 底部一行「还有 2 位好友没有共享」就够了。不要让人感到被拒绝。

一起的首屏把「你」放在第一扇窗，标「你」。用户先看见自己的窗，再看朋友的。空状态保留 v0.2 的「一个人关灯，也成立。」

### 3.4 回灯：让回灯是一张「不一样的卡」

v0.2 的回灯是「把同款窗景发回原聊天」。问题是，**同款卡看起来像原样退回，不像回应。** 而且原发送者不会收到任何通知，这个动作很容易被忽略。

v0.3 建议给回灯一张独立的卡：

- 卡面还是同一扇窗，但暖光在另一侧，或窗台多一颗小星；
- 标题：**「灯还给你。」**
- 落地页：**「灯回来了。」** + 「今晚也早点睡。」 + 「我也关灯」；
- 不显示发件人昵称、UID、时间、历史；不新增消息、收件箱、已读或回灯通知。

回灯的动作要快：**点「回一盏灯」直接调起分享面板，不再让用户选文案。** 留灯是「我想说一句」，回灯是「我收到了」，后者应该比前者少一步。

三句可用的回灯文案：

- 「收到了。今晚早点睡。」
- 「还你一盏，晚安。」
- 「我也关灯了。」

回灯卡带一个不透明的 `reply` 标识，服务端只用于统计「回灯卡生成 / 被打开」，不用于识别谁回了谁。原发送者不需要在小程序里看到「TA 回了你」；如果回灯卡发回同一个聊天，那条卡本身就是回执。

### 3.5 夜空：不要空白窗格

v0.2 说「空白窗格表示那一晚没有记录」。一排空框会像缺了几颗牙，仍然是损失框架。

建议：**每一晚都是一扇窗。** 没有记录 = 暗的、没有星的窗；有记录 = 暗窗 + 一颗星；今晚还没关 = 暖窗。这样七晚是一面完整的墙，而不是七个格子里的几个空洞。

三十晚不要用带格线的网格。用一片固定的星野：有记录的位置亮一颗星，没有记录的位置就是夜空。没有「空格」，只有「今晚没有亮」。

按时和较晚继续用同一种星。为了让「连续」不显得莫名其妙，在私密的「记录详情」里加一句：

> 连续只统计在目标时间前关灯的夜晚；晚一点，也会留下一颗星。

记录详情只对自己开放：日期、按时/晚一点/没有记录、关灯时间、当晚的晚安签。没有好友、没有排名、没有「你击败了谁」。

### 3.6 晚安签：本地短句是基线，陌生人的话是加成

v0.2 让完成页直接显示一条从公共池抽到的心语。这个情绪很强，但也很脆：一条不合适的签会毁掉整个完成页。

建议把主次倒过来：

- **完成页首先为本地短句设计。** 内置短句不是「抽不到时的兜底」，而是基线。没有公共池、审核服务挂了、内容被下架，完成页仍然是完整的。
- **抽到签时，用同一版式替换本地短句。** 不换布局，不换字号，不额外弹窗。
- **只抽没有成立举报、评分不为负的签。** 没有合格的签就用本地短句。
- **来源标注必须匹配。**
  - 收到的签：「来自一位也关灯的人 · 匿名」
  - 本地短句：「今晚关灯」
  - 不要用「晚安心语 · 匿名」这种半旧半新的名字。
- **加一个很轻的「内容不合适？」。** 点开后不离开完成页，提交举报后立刻换成本地短句。不要为了稳定而让用户忍着读。
- **长签降一级字号，不截断。** 最多 80 字；超过 40 字时字号降一档，保持可读。

统一叫「晚安签」。「晚安心语」只作为内部池子的名字，不再出现在用户界面。

### 3.7 窗台：猫还是植物，选一个

v0.2 说「植物或猫」，这是品牌识别点，不能两个都留。建议选**猫**：

- 它是一个有生命的剪影，能让窗看起来真的有人住；
- 它给 8 秒演示增加第二个角色：人按灯，猫在窗台看着；
- 它比植物更容易被记住，也更容易成为分享卡上的视觉钩子。

但只做剪影：背对镜头，没有眼睛，不拟人，不卖萌。猫不参与文案，不叫「喵」，不拟声。它只是在那里。若测试反馈「太可爱、削弱了克制的语气」，再退回一盆植物。

### 3.8 把提醒移出 P0/P1

v0.2 已经把提醒独立排期，v0.3 建议再退一步：**在自然回访验证之前，不上提醒。**

否则第二周的留存会被「提醒」污染，分不清用户是想回来，还是被叫回来。P1.5 单独找 10 位用户测试「提醒我一次」，一条模板，目标前 10 分钟，文案：

> 窗还亮着。困了就关掉它。

不写「你还没关灯」。没有合适模板就不上，不阻塞主版本。

## 四、传播的第二引擎：8 秒

v0.2 的留灯卡是一对一的。要让产品「有影响力」，还需要一对多的内容。最好的内容不是功能介绍，而是那个动作本身。

### 4.1 8 秒脚本

| 时间 | 画面 | 声音 |
| --- | --- | --- |
| 0.0–2.0s | 亮窗，窗台有猫的剪影，窗上显示 22:30 | 夜里的低频环境声 |
| 2.0–3.2s | 一只手入画，按住灯绳，暖光开始收拢 | 轻微的按压声 |
| 3.2–4.4s | 灯灭，星空浮出，一颗流星划过 | 一声很轻的「嗒」 |
| 4.4–6.2s | 一句晚安浮出：「今天就到这里。剩下的，明天再说。」 | 安静 |
| 6.2–7.2s | 手指点「放下手机」 | 无 |
| 7.2–8.0s | 屏幕暗下，只剩一行小字：今晚关灯 | 安静 |

不配音，不解释，不加「快来试试」。字幕只有一句晚安和产品名。先拍 3 条：单人版、双人版（两扇窗）、猫的视角。投视频号、小红书、朋友圈；不投信息流广告。第一条的目标不是转化，是让人看完 8 秒。

### 4.2 分享资产

- **留灯卡图**：5:4，500×400，一扇窗 + 很小的 `LIGHTS OUT`，不放大段文字，不放 UID。
- **聊天标题**：用户选中的那句晚安，不是产品口号。比如「今天辛苦了，困了就去睡。不用回我。」
- **邀请卡**：5:4，两扇窗，一扇亮一扇暗；标题「今晚一起关灯吗？」；不显示发起人的状态。
- **朋友圈/视频号标题**：「今晚关灯｜一个会催你走的小程序」。这是唯一可以使用产品口号的地方。

聊天里不写增长文案。让那句晚安自己说话。

### 4.3 叙事

这个产品可以有一个很清晰的反面立场：

> 不是所有产品都应该争夺你的时间。我们把成功定义为：你多快离开。

这句话适合做发布文章、媒体采访和视频号简介。它不需要证明「早睡能治百病」，只需要诚实地说明：这是一个让你结束今天的小工具。影响力来自立场，不来自功能数量。

## 五、修订后的页面与流程

| 页面 | 变化 |
| --- | --- |
| 今晚 | 完成页加一行「想留给谁，就留一盏灯」的轻文字（A/B）；其余保持 v0.2。 |
| 夜空 | 七晚窗格改为「每夜一扇窗」，没有空框；三十晚改为星野；新增私密记录详情；**移除「留灯」入口**，只保留「给下一个关灯的人留一句」的公共投稿（规则沿用 v0.2：每周期 1 条、80 字、自动审核、失败留草稿、可举报）。 |
| 一起 | 好友状态改为五态；新增共享同意卡；首屏第一扇窗是「你」；未共享不逐行展示。 |
| 我的 | 新增「让好友看见我今晚是否关灯」总开关；提醒延后。 |
| 留灯卡 | 三句预设；接收页三动作；来源标注；回灯是独立的卡。 |
| 好友邀请 | 两步：接受邀请 → 共享开关；发起人信息只显示称呼和共享说明，不显示状态。 |
| 记录详情 | 新增：日期、状态、时间、晚安签；连续口径说明。 |

留灯流程：

```text
完成关灯 / 一起
      ↓
选一句预设
      ↓
微信分享
      ↓
收卡人：我也关灯 / 回一盏灯 / 先收下
      ↓
回灯卡「灯还给你」回到聊天
```

邀请流程：

```text
邀请卡（两扇窗）
      ↓
接受邀请
      ↓
共享开关（默认开，可关）
      ↓
一起：看见彼此的窗
```

## 六、指标与停止线

保留 v0.2 的指标，不重复。新增或明确这些：

| 指标 | 口径 | 内部判断线 |
| --- | --- | --- |
| 完成页留灯入口打开率 | 打开留灯面板 / 完成页展示 | B 版 ≥5%，且退出时长不恶化；低于 3% 说明入口不可发现 |
| 留灯生成率 | 调起留灯分享 / 完成关灯 | 先观察，不设硬目标；分享调起不等于发送成功 |
| 回灯生成率 | 调起回灯分享 / 有效卡打开 | ≥15% 才值得继续做回灯；低于 10% 不要做收件箱 |
| 发卡人复投率 | 14 天内发过 2 张以上卡的人 / 发卡人 | ≥20% 说明卡片本身值得反复用 |
| 邀请接受率 | 接受邀请 / 打开邀请页 | ≥40% 说明邀请卡和共享说明说得清楚 |
| 一起回访 | 有共享关系的好友对中，在不同夜晚打开「一起」≥2 次的比例 | ≥30% 才值得做双人窗 |
| 完成到退出 | 晚安签完全显示到进入后台；另记从确认成功起算的总时长 | 中位数 ≤10 秒；「看看夜空」单列 |

**停止线比目标更重要。**

- 如果完成页的轻文字让退出变慢、访谈里出现「被要求分享」，删掉它。
- 如果回灯生成率低于 10%，不要做回灯通知或收件箱，先改卡片。
- 如果「一起」的回访低于 15%，不要做双人窗；先确认用户是否真的想看朋友的窗。
- 如果留灯分享调起率低于 3%，先改 8 秒演示和卡片，不要加游戏化。
- 不要用「连续」来救留存。连续是最容易做、也最容易伤害目标用户的手段。

## 七、验证

v0.2 最后列了三个体验。v0.3 加第四个：

1. 按住一扇窗，是否比普通按钮更有结束感？
2. 完成后，用户能不能顺手离开？
3. **关灯后，用户会不会主动去找「留灯」？** 如果不找，是不知道，还是不想？
4. 收到卡的人，会不会自然想回一盏灯？

第三点最容易被忽略，也最影响传播。验证方法不是问「你会分享吗」，而是给用户一个真实的场景：

> 今晚关一次灯，然后做你本来要做的事。
> 如果你想把今晚留给一个人，你会怎么做？

不要提示入口。观察他是否找到完成页的那行字、是否去「一起」、是否直接放弃。访谈追问：

- 关灯后，你有没有想起一个人？为什么没有发？
- 回灯和回消息，你觉得区别是什么？
- 如果这个产品明天消失，你会想念哪一部分？

A/B 的样本不用大：A 组 10 人，B 组 10 人，定性为主，描述性数据为辅。不要把它当成统计显著性实验，它只是帮我们判断「这行字是否冒犯」。

首轮通过线沿用 v0.2：10 位单人里 8 位完成第一次关灯，6 位能说出「关灯=准备睡」，5 位愿意发给具体的人；5 对里 4 对完成一次双向留灯；5 位收卡人里 3 位完成第一次关灯；第二周 30% 完成三晚。

## 八、技术与数据契约

1. **好友状态枚举。** 服务端按好友自己的周期返回 `not_open / open_no_record / closed_record / closed_no_record / not_shared`，只带称呼、状态、`sameCycle` 和必要标识。旧接口也要遵守共享开关，避免旧客户端绕开权限。
2. **共享字段。** `users.shareTonight` 默认 false；新邀请接受时由用户在第二步显式开启；旧关系保持 false，由「一起」的一次性提示开启；「我的」有总开关。关闭后，好友查询直接不返回该用户的状态。
3. **卡片集合。** `share_cards` 保存 `_id`（不透明）、`purpose`（`light / reply / invite`）、`lineId`、`fromUid`（仅服务端使用，永不返回）、`replyTo`、`createdAt`、`expiresAt`（暂定 7 天）、`revokedAt`、`openCount`。链接只带 `light / reply / invite` 参数，不带 UID，不带昵称。
4. **回灯归因。** `reply` 卡带 `replyTo` 只用于统计生成与打开，不用于识别谁回了谁；产品内没有「回灯通知」。
5. **晚安签质量。** 抽签时排除有成立举报、评分为负的内容；没有合格内容时返回本地短句。举报后立即失效并换成本地短句。来源字段随内容一起返回，前端不自行猜测。
6. **分析事件。** 只记录：进入、设时间、按压开始/取消/完成、打卡结果、完成页展示（签来源：收到/本地）、退出点击/结果、夜空打开、签举报、留灯面板/分享调起、卡片打开、我也关灯、回灯调起、邀请页/接受/共享开关、一起打开/好友窗点击。不记录正文、昵称、具体时间、好友名单。
7. **开关与回退。** 新首页、完成页轻文字、留灯、一起、提醒分别控制；新旧界面共读记录；回退后仍能读到新版打卡。
8. **兼容。** 保留 `pages/home`、`pages/friends`、`pages/profile`，新增 `pages/nights`；旧 `ref` 分享链接继续可进入，但新的留灯、回灯、邀请链接不复用 UID。旧心语奖励保持原归属；心语查询失败不阻断关灯。

## 九、需要拍板

1. **完成页加不加那行轻文字？** 建议做 A/B，而不是直接拍板。若 B 不伤害退出，保留；若用户觉得被要求分享，删掉。
2. **新好友接受邀请时，共享默认开还是关？** 建议默认开，但在第二步显式展示开关和范围；旧关系仍默认关。若你更看重隐私，默认关也可以，但「一起」首屏会更空，需要用一张开启卡承接。
3. **窗台选猫还是植物？** 建议猫，剪影、不拟人、不卖萌。若测试觉得太可爱，退回植物。
4. **夜空里要不要留灯？** 建议移除。夜空只做私人回看和公共投稿；留灯留在完成页的轻文字与「一起」。两个社交动作不要在同一个页面打架。
5. **提醒是否延后？** 建议延后到 P1.5/P2，先测自然回访。提醒会污染留存数据。
6. **回灯是否用独立卡？** 建议是。没有独立卡，回灯只是把原卡退回去，发送者很难感到「被回应」。

确认这六件事后，下一步不是铺页面，而是：先拍 8 秒演示，再做完成页 A/B 的可点原型，最后用 5 对熟人验证「关灯 → 留灯 → 回灯」。双人窗、排行榜、群房间、商业化都排在验证之后。
