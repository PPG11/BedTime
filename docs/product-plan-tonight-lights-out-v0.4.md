# 今晚关灯产品方案 v0.4

2026-11-07 · 设计评审稿

**一个会催你走的小程序。** 打开一扇暖窗，按住关灯，读一句晚安，点「放下手机」离开。想起一个人时，可以从「一起」留一盏灯。对方收到的是一句完整的晚安，愿意的话，可以回一盏灯，或关自己的灯。

首批服务已经想休息、却还在刷手机的人。熟人传播先找本来就会互道晚安的朋友、伴侣和室友。个人仪式能否让人第二周主动回来、收到留灯的人是否愿意回应、8 秒演示能否让新用户看懂，都单独验证。 [v0.3 设计稿](product-plan-tonight-lights-out-v0.3.md)

## 今晚

### 从开窗到关灯

第一次打开直接展示暖窗和一句「准备休息时，来关一次灯」。时间预设 22:00、22:30、23:00，支持自定义，默认 22:30。用户可直接点「先这样，今晚试试」。从留灯卡进入时先完整展示卡片，点「我也关灯」后才要求确认自己的时间。已有用户使用原目标。

新版展示窗口为 **目标前 3 小时起，至目标后 6 小时前**。关灯请求、记录恢复与历史继续使用现有服务端周期和档案时区。服务端保留目标前 12 小时的兼容窗口，旧客户端提前写入了记录时，新版在该周期直接恢复完成态。 [现有时间规则](../cloudfunctions/common/time.js) · [业务链路](checkin-and-friends-backend.md)

| 目标 | 新版仪式窗口 | 关闭时 |
| --- | --- | --- |
| 22:30 | 当天 19:30 至次日 04:30 前 | 04:29 仍属上一晚，04:30 切到下一周期。 |
| 00:30 | 前一晚 21:30 至当天 06:30 前 | 前一晚 23:30 可关灯，归入 00:30 的目标周期。06:30 切到下一周期。 |

未开窗时，亮窗下只提示「今晚 19:30 开窗」。已开窗时，首屏是一扇窗、一句状态和一个主操作，目标放在「我的」。过了目标仍可做同样的动作，文案用「晚一点，也可以把今天放下」。

改目标时保留已经开启的当前仪式窗口，以及最近一条记录所属的窗口。若新窗口和它们重叠，新目标延到第一个不重叠的完整窗口生效，设置页显示生效时间。例如 23:30 已按 22:30 的目标关灯，再改成 00:30，当晚仍恢复原来的暗窗。新时间从次日晚 21:30 开始。现有服务端会随目标变更立刻重新算周期，因此上线前需要服务端保存生效边界，并让新旧入口共用。 [现有目标更新](../cloudfunctions/common/users.js)

### 按住和松手

原型起点为 800ms。按下时暖光立即收拢，进度由光线表现。达到阈值前松手、滑出按钮或退到后台，光线恢复。达到阈值后只提交一次，显示「正在确认…」，收到服务端确认才熄灯、留下星点。首次就可使用低强调的「轻点关灯」，两种入口走同一提交。

默认静音，确认成功时可用一次轻震动。减少动效时用静态亮窗和暗窗。手势开始时固定账号、精确目标和周期，到阈值时再校验。超时提示「还没确认，再试一次」，按原周期恢复记录或重试。按压跨关闭或中途改目标时，先刷新状态，请用户确认是否在新周期重新操作。

### 完成和离开

全屏夜色，暗窗旁一颗星。直接展示一条晚安签。主操作是「放下手机」，下方是「看看夜空」。点主按钮时尝试 `wx.exitMiniProgram`，不支持或调用失败时保留完成态并提示用微信自带入口退出。退出代表离开小程序，是否放下手机通过次日回访问。 [微信退出接口](https://github.com/wechat-miniprogram/api-typings/blob/v3.12.3/types/wx/lib.wx.api.d.ts#L22733-L22744)

完成页的留灯脚注**默认关闭**，另做实验。A 版只有退出和夜空，B 版在留白后加「想留给谁，就留一盏灯 ›」。B 版要有清楚的可点语义和足够触控区，视觉上保持低强调。原型先看用户能否顺手退出、是否觉得被要求分享。只有真实卡片带来可观察的下游打开、退出体验也守得住，才考虑开启。常驻留灯入口在「一起」，因此 A 版用户仍能主动找到。

## 晚安签与夜空

**本地短句是完整的完成态。** 「今天就到这里。剩下的，明天再说。」署名「今晚关灯」。完成页只呈现一句。启用公共池后，服务端确认打卡，再独立读取或分配晚安签，首轮等候上限可按约 350ms 验证。来得及就用同一版式展示，署名「来自一位匿名伙伴」。池空或超时就选本地句，本次停留及同设备同周期重进保持这句。迟到的签只进入夜空回看。已有分配按用户和周期恢复，重复请求不刷出新签，下架内容改用本地句。 [现有打卡写入](../cloudfunctions/common/checkins.js) · [现有心语分配](../cloudfunctions/common/goodnight.js)

**公共投稿和私人留灯各走各的。** 夜空里的「给下一个关灯的人留一句」每周期最多成功投稿一次、最多 80 字。提交显示「正在检查…」，沿用微信 `msgSecCheck` 自动审核，通过才入池。未通过提示修改，接口异常保留草稿供重试。抽取只选可分发的合格内容，排除本人。投稿和领取彼此独立，无需站长逐条审核。

**举报先解决读者此刻的体验。** 只有实际收到该签的账号可以举报，重复操作合并。举报后对本人立即换成本地句，跨重进生效。首轮以两位不同领取者的有效举报为暂停分发的起点，确认违规后全局下架，复检结论不明确时维持暂停。正式开放公共池前，验证下架后无法从旧签、历史或缓存读回原文，并准备可独立切回本地句的开关。

**七晚是一面完整的窗。** 每晚都有一扇窗，有记录便留一颗星。按时和较晚是同一颗星。无记录的往夜用暗窗，今晚仍在等待关灯时是暖窗。三十晚用无格线星野，固定位置对应周期日。点击窗格可以看个人记录，私密详情收纳累计、连续和近期最佳。连续只计目标时刻及之前的记录，较晚仍计累计。近期最佳的范围标为最近加载的 365 次记录。夜空保留公共投稿和晚安签回看，留灯从「一起」进入。 [统计口径](checkin-and-friends-backend.md)

## 留灯和回灯

两张卡在微信聊天里流转，用户自己选择聊天。留灯卡是一扇暖窗和一句预设晚安，主文案可用「今天辛苦了，困了就去睡。不用回我。」收到后可以点「我也关灯」「回一盏灯」，也可以直接离开。

回灯用独立的「灯还给你」卡。沿用同一扇窗，在另一侧加一点暖光或一颗小星。点击直接调起分享，固定句「收到了。晚安。」落地页写「灯回来了」，可以进入自己的关灯场景。回灯卡无需再提供一次回灯动作，一来一回自然收尾。分享前卡片准备失败时，允许重试，读卡和个人关灯照常可用。

| 动作 | 成立条件 |
| --- | --- |
| 收到晚安 | 有效留灯或回灯卡被打开，直接展示预设内容。 |
| 回灯 | 点击调起分享记作一次意愿信号。新卡实际被打开，才记一次下游打开。 |
| 关灯 | 用户主动长按或轻点，且服务端确认写入。回灯不写打卡。 |
| 成为好友 | 使用独立好友邀请或好友码，双方确认关系。留灯与回灯不建立关系。 |

新卡链接使用有用途和期限的随机标识，初期七天。留灯、回灯和好友邀请分开解析，非法或混用的标识降级为对应的通用页。留灯与回灯卡面和落地页都不展示发件人昵称、UID、目标或历史。回灯关联只用于计算原卡到新卡的流转，过期或撤回后停止来源归因。卡片可以转发，打开事件只说明有人打开，无法据此认定对方就是原聊天里的收件人。 [CloudBase 带参分享说明](https://docs.cloudbase.net/recipes/add-share-with-params-miniprogram)

## 一起和好友

首屏先看到自己的窗，再看到向自己授权的好友窗。自己用完整的今晚状态。好友窗按每位好友的有效就寝周期计算，顶部注明「每扇窗按各自的夜晚更新」。当晚有记录时出现「已关灯」星点，其余时候是一扇中性的窗。中性窗不推断对方睡了没有。未共享的好友仍在关系管理里。首屏空状态是「一个人关灯，也成立」。

**好友卡可以转发，所以打开卡片后只能申请。** 在「邀请好友」里发卡，对方点「申请一起」，由发卡人确认。卡过期或撤回后可以回到今晚。已经发出的申请从好友管理独立处理。12 位 UID 叫「好友码」，放在「我的」和邀请页备用。输码继续沿用现有申请流程。 [好友码生成](../cloudfunctions/common/users.js) · [好友申请逻辑](../cloudfunctions/common/friends.js)

**每位好友分别授权。** 建立关系与共享状态是两个动作。确认好友时可选「仅加好友」或主动选择「也让这位好友看见我今晚是否关灯」。默认不共享。每条已接受关系保存双方各自的选择，只有发起共享的一方的数据可以被对方看见。旧关系同样从关闭开始。「我的」可暂停全部共享，恢复时只恢复仍有效的已授予关系。单独撤回或解除关系立即停止服务端读取。前端回到前台重新拉取，切换账号、请求失败或授权失效时清除旧状态。

**好友端只取必要的信息。** 返回可见称呼、关系操作所需标识和经授权的当晚记录状态。目标时间、档案时区、具体打卡时间、连续、历史和开窗阶段留在本人视图。现有周期关窗即切换，好友无需判断「关窗但漏记」。公开开窗状态的变化还可能暴露目标作息，因此好友端也不发 `sameCycle` 或开闭窗边界。旧客户端查询同样遵守授权和字段裁剪。 [现有周期切换](../cloudfunctions/common/time.js) · [现有好友返回字段](../cloudfunctions/common/friends.js)

## 视觉与 8 秒演示

夜间只有一处暖光。窗框、窗台、玻璃反光和一点水汽先给窗建立质感。窗台放一只背对镜头的猫剪影，只做品牌识别。标题和晚安签用宋体，正文和操作用无衬线。全天统一夜色，亮暗变化由窗承担。

- 夜色主背景 `#080C18`，暖光 `#F2B36B`，正文 `#F4EFE5`，弱化文字从可读的实色起调。实测深底对比度。
- 主操作至少 44px 高，覆盖 320px、系统放大字号和弱动效。80 字晚安签允许换行，保证退出按钮仍可触达。
- 微信卡面按 5:4 构图。留灯是暖窗，回灯用另一侧暖光或星点，好友邀请用两扇窗。聊天里的标题优先保留一句有内容的晚安。 [微信分享卡图示例](https://docs.cloudbase.net/recipes/add-share-with-params-miniprogram)

**先拍一条真实的 8 秒演示。** 它是独立传播素材，也能用来判断动作是否易懂。

| 时间 | 画面 |
| --- | --- |
| 0–2 秒 | 暖窗和猫剪影，手进入画面。 |
| 2–3.2 秒 | 按住，暖光收拢。 |
| 3.2–4.4 秒 | 灯熄灭，留下一颗星。视频可加一声很轻的「嗒」。 |
| 4.4–6.2 秒 | 读到「今天就到这里。剩下的，明天再说。」 |
| 6.2–8 秒 | 点「放下手机」，拍到实际退出小程序，再把手机扣下。收尾出现「今晚关灯」。 |

先看用户看完后能否说出「这是我睡前可以做的一件事」。视频号、小红书和朋友圈各自看完播与评论。渠道具备可验证的入口时再统计首次打开与首晚关灯。无法准确归因的渠道单独记录互动，避免把播放量当成激活。

## 验证与发布顺序

| 阶段 | 交付 | 决策依据 |
| --- | --- | --- |
| 原型 | 长按与轻点、纯完成页、脚注版本、留灯和回灯落地、逐关系授权、8 秒录屏 | 约 10 人做任务，至少 8 人能自己完成第一次关灯并讲清记录含义。脚注比较先观察注意力、压力和退出动作。 |
| P0 个人仪式 | 今晚、退出、七晚夜空、本地晚安签、静态留灯样例 | 完成态到小程序进入后台的中位数目标 ≤10 秒。用两周试用观察主动复用，首轮目标为第 8–14 个周期关灯至少三晚的人占 30%。 |
| P1 熟人互动 | 留灯、独立回灯卡、好友邀请、好友窗与授权。公共晚安签达到匿名、审核、举报和回退条件后单独开启 | 先观察约 5 对熟人怎样回应，再追踪实际打开、首晚写入、不同夜晚回访。有复用证据后再排双人窗。 |
| P1.5 提醒 | 自然回访试验完成后，独立小流量试「提醒我一次」 | 核对后台模板和真机授权，符合条件才开放。提醒默认关闭，用户主动订阅后，同一周期最多发一条。 |

提醒首轮用目标前 10 分钟，文案按可用模板配置。一次性授权只对应一次发送。发送前核对用户授权、目标和周期、是否已关灯，改目标导致原计划失效、取消或过期时停止发送。以账号和周期去重，发送结果不明时不自动重发。提醒组与自然回访组分别报告。 [腾讯云订阅消息说明](https://cloud.tencent.com/document/product/1301/103770)

### 统一指标

| 要判断什么 | 统计口径 |
| --- | --- |
| 收尾是否够短 | 从服务端确认到进入后台，另记晚安签首次展示时点。报告 10 秒内退后台的比例、可观测时长中位数和观察窗结束仍在前台的人数。「看看夜空」不算退出。 |
| 用户会不会自然回来 | 最近 7 个完整个人周期至少关灯 3 晚的用户数和占比。第二周以有完整观察期的首周激活用户为分母，研究任务和提醒带来的打开另列。 |
| 留灯能否带来新用户 | 调起分享、有效新访客打开、48 小时内首次服务端关灯、回灯卡实际打开分别计数。按账号和来源去重，重复打开不重复计激活。 |
| 好友窗有没有陪伴价值 | 以有授权且能看到窗景的好友对为分母，观察不同夜晚的「一起」回访。比较是否愿意再看一眼，以及未共享用户能否理解空状态。 |
| 写入是否可靠 | 同一用户与周期去重，记录最终成功、超时后恢复、切周期及失败。有效提交最终成功率的首轮目标 ≥99%，同时报告实际次数。 |

原型每组 10–15 人时，一次行为就会让比例变动约 7–10 个百分点。这一轮用于观察脚注是否抢视线、是否让人感到需要分享。正式决定脚注去留前，按账号固定分组，以首个符合条件的周期比较退出和卡片有效打开。先明确可接受的退出影响与所需样本量，达不到样本门槛时维持 A 版。留灯、回灯和好友窗也分别按下游行为决定投入，任务中被要求发的卡与试用者主动发的卡分开看。

## 上线前验证

1. **共用原来的打卡记录。** 新首页先拿个人档案和当晚状态，夜空历史延后。保留旧路由和原记录、目标与统计契约。新首页、完成页脚注、晚安签、留灯、一起与提醒分别控制。
2. **打卡和晚安签隔离。** 新版打卡先完成服务端幂等写入，心语读取或分配独立。所有返回给领取者的入口一起换成不透明引用，包括旧版打卡提交、状态、历史与签详情。现有 `uid_date` 能推回作者 UID，改动覆盖 `goodnightMessageId` 和心语文档 ID 两条路径。 [打卡返回](../cloudfunctions/common/checkins.js) · [心语返回](../cloudfunctions/common/goodnight.js)
3. **两账号验好友，三账号验转发。** 覆盖卡被转发后第三人申请、邀请人拒绝、单方授权、撤回、解除再添加、旧客户端及返回前台。关系接受与共享失败可独立恢复，重复请求不扩大权限。
4. **按同一周期核对交互。** 验证 22:30 和 00:30 开窗、闭窗及跨午夜，旧客户端提前写入后恢复，超时已写入后重试，重复点击和后台中断。测 22:30 与 00:30 双向改目标、同半小时档改目标、改时后重进，确认旧手势不会写到新周期。验晚安签空池、超时、重复分配、本人排除、举报隐藏和下架。
5. **真机确认边界。** 改代码后运行 `yarn verify`，在模拟器检查 320px、长句与放大字号。用 iOS 和 Android 验证长按、轻点、退出失败回退、微信卡片冷启动与热启动、过期、转发、审核与一次性订阅。分析只存完成指标所需的事件、去重标识和状态类别，正文、昵称、好友名单和具体目标时间留在各自业务域。
