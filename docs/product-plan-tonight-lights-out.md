# 今晚关灯 · 产品方案 v0.2

2026-11-07 · 设计评审稿

本稿替代 v0.1。v0.1 把风险、数据和工程边界写得很稳，但更像一份「验证方案」，还不是一份「会被人记住、愿意转发的产品方案」。v0.2 保留 v0.1 的核心判断，重做情绪、社交和视觉。

## 一句话

**一个只催你放下手机的小程序。**

每晚，你看见一扇亮着的窗。按住，直到灯熄灭；收下一句晚安，然后把手机放下。你也可以给在意的人留一盏灯，TA 可以回一盏，不用聊天，也不用欠人情。

## 相对 v0.1 的六个变化

| 维度 | v0.1 | v0.2 | 为什么 |
| --- | --- | --- | --- |
| 核心动作 | 点一下关灯 | **按住 600–900ms**，光逐步收拢，震动，熄灯 | 把动作变成可感知、可拍成 8 秒视频的仪式 |
| 完成态 | 提示「手机可以放下了」 | **全屏晚安 +「放下手机」退出 + 留灯** | 让「放下手机」成为机制，而不是一句文案 |
| 社交 | 单向留灯卡，收卡人可读完离开 | **留灯 / 回灯**，收卡人可一键回灯并完成自己的第一次关灯 | 单向贺卡没有循环；回灯把传播变成两次仪式 |
| 统计 | 首屏连续、完成率、按时次数 | **首屏零数字**；夜空用星图，数字折叠 | 对最需要早睡的人，KPI 会变成新的焦虑 |
| 关系 | 双人窗放在 P2 | **P1 先做轻量「一起」**，只显示今晚是否关灯 | 关系是留存与传播的核心，不该等太久 |
| 视觉 | 深靛蓝 + 暖琥珀的卡片式界面 | **真实窗、宋体、颗粒、单一暖光** | 避免变成另一套「深色渐变卡片」模板 |

保留 v0.1 的判断：关灯是核心动作；暖窗是视觉记忆点；首屏只做一件事；收尾时长中位数不超过 10 秒；保留打卡与用户数据；心语移出关灯关键路径。

## 用户与洞察

**核心用户。** 20–35 岁，知道该睡，却总想「再看一会儿」的微信用户。不是缺知识，也不是缺决心，而是缺一个「结束今天」的动作。

**传播用户。** 异地伴侣、室友、闺蜜、总在微信里互道晚安的朋友。他们想表达在意，但不想开启一段聊天；一句「我先睡了」常常显得敷衍，一张留灯卡刚好。

**洞察。**

- 睡前阻力不是信息，是「结束」的成本。关灯比打卡更像一个真实的结束动作。
- 一句晚安需要一个动作承接。只发文字，容易变成社交任务；先关灯，再留灯，话就变轻了。
- 关系里的压力要低。「不用回我」比「记得回我」更有力量。
- 用户不想被教育，也不想被统计。产品只需要在正确的时刻，把灯递到手里。

**不服务的人。** 需要专业睡眠干预的人；追求排行榜、打卡连续和自律竞赛的人。后者不是目标，也不应该成为产品语气。

**JTBD。** 在 30 秒内，给自己一个结束今天的理由；让在意的人知道「我也要睡了」，但不必开启对话。

## 产品原则

1. **关灯即完成。** 按时与较晚只留在个人记录里，不惩罚、不追问、不出现「断签」。
2. **只做一个动作，做完就离开。** 首屏没有第二个主按钮；完成态不提供信息流。
3. **关系要轻。** 留灯不是礼物，回灯不是义务；不收钱、不排名、不显示已读。
4. **数字退后，夜晚在前。** 先看见窗、星和一句话，再看见次数。
5. **一扇窗贯穿，但每页只讲一件事。** 今晚讲关灯，夜空讲回看，一起讲陪伴，我的讲设置。
6. **不制造焦虑，也不假装社交。** 没有好友也能完整使用；没有连续也值得回来。

## 核心体验：今晚

### 第一次打开

首页直接预览一扇亮窗，底部只有一行：「准备休息时，来关一次灯。」

首次进入弹出一张很轻的时间卡，而不是完整设置页：

- 22:00 / 22:30 / 23:00 / 自定义
- 默认 22:30
- 「先这样，今晚试试」

昵称、好友、头像都可以稍后处理。第一晚不需要注册感。

### 仪式窗口

服务端的打卡窗口保持「目标前 12 小时、目标后 6 小时」不变，兼容已有数据和旧客户端。但客户端另设一个**仪式窗口**：

- 目标前 3 小时开窗；
- 目标后 6 小时仍可关灯；
- 更早时只展示亮着的窗和「今晚 19:30 开窗」，不出现关灯按钮；
- 更晚时进入下一周期，首页显示「今晚的窗还没开」。

这样，22:30 的目标不会在上午 10:30 就允许「关今晚的灯」。这是产品语义，不是服务端规则。

### 首页状态

| 场景 | 用户看到 | 行为 |
| --- | --- | --- |
| 加载中 | 一扇正在亮起的窗骨架 | 不显示按钮 |
| 未开窗 | 亮窗、目标时间、「今晚 19:30 开窗」 | 可改目标、看夜空 |
| 已开窗，未到目标 | 亮窗、「按住关灯」、距离目标的时间 | 一次按住提交 |
| 按住中 | 光随按压逐步变暗，百分比/灯绳反馈 | 松手可取消；按满即关 |
| 已松手，等待服务端 | 窗保持熄灭中，文案「正在确认这盏灯…」 | 不可重复提交 |
| 关灯完成 | 暗窗、星光、一句晚安、「放下手机」 | 可留灯、看夜空 |
| 已关灯后重进 | 直接进入完成态 | 不重复动画、不重复提交 |
| 网络失败 | 光重新亮起，「没关成，再试一次」 | 原位重试，保留按钮 |
| 周期刚切换 | 新周期未开窗状态 | 不把上一晚的结果带进来 |

### 关灯动作

- **按住 600ms** 开始收拢光线；按满约 900ms 完成。松手过早则恢复，文案提示「按住不放，灯就会灭」。
- 连续两次没按满，出现「手酸了？轻点一下也能关灯」的兜底；保留可访问性。
- 开始与完成各一次轻震动。完成时不再弹「打卡成功」Toast，动画本身就是反馈。
- 服务端确认后再播放最后的熄灯与星光；确认前不要把页面提前切走。
- 动效只播放一次。系统开启「减少动态效果」时，直接切到静态暗窗。

### 完成态

这是产品的情绪峰值，也是传播起点。

```text
        ┌────────┐
        │  暗窗  │  ·
        └────────┘

           灯灭了。
     今天就到这里。
     剩下的，明天再说。

     — 今晚关灯

     [   放下手机   ]
     今晚不再打扰

     [ 给 TA 留盏灯 ]  [ 看看夜空 ]
```

- 主按钮「放下手机」调用 `wx.exitMiniProgram`；失败时提示从右上角退出，不阻断。
- 次按钮「给 TA 留盏灯」打开分享面板。
- 底部只保留一条很轻的七晚窗格，不做统计。
- 若今晚收到了别人的晚安签，出现一张可拆开的窄卡：「今晚的晚安签 · 有人也给你留了一句话」。
- 若比昨晚早，出现一行：「比昨晚早 12 分钟。」只和昨天的自己比，不排名。

### 晚安签

保留现有「关灯后收到一句晚安心语」的能力，但从首页移到完成态和夜空：

- 关灯成功、服务端返回奖励后，完成态出现「晚安签」入口；
- 打开是一张夜间卡片：一句审核通过的心语 +「喜欢 / 不太合适」；
- 同一晚稳定，不刷新出新句子；
- 心语查询失败不阻断关灯，也不阻断完成态；
- 用户投稿放在夜空，作为次级动作，不在关灯前要求写作。

## 夜空

夜空不是统计页，是「你为自己关过的灯」的星图。

### 首屏

- 一句大字：「你已经为自己关了 32 次灯。」
- 一句轻文案：「没有连续也没关系。回来关灯的这一晚，只属于这一晚。」
- 最近七晚的窗格：已关灯是暗窗 + 星，晚一点是暗窗 + 淡星，未关灯是空窗，今晚未关是亮窗。
- 最近三十晚的星点网格：一格一晚，不做「缺失」的红色标记。

### 次级

- 累计关灯、当前连续、最长连续、完成率，全部折叠在「数字」区域；
- 当前连续只作为私密数据，不出现「你已断签」；
- 收到的晚安签、自己的投稿；
- 「给下一个关灯的人留一句」入口。

### 不做什么

- 不做排行榜；
- 不做「本周击败了多少人」；
- 不做连续中断的推送；
- 不把「按时率」放在第一屏。

## 一起

「一起」是关系页，不是好友管理页。先看见窗，再看见人，最后才是好友码。

### 首屏

```text
今晚，3 扇窗和你一起暗下来。

[你] [友] [友] [友] [友] ...

┌──────┐  ┌──────┐
│ 暗窗 │  │ 亮窗 │
└──────┘  └──────┘
  阿澈       小满
  已关灯     还亮着
```

- 好友的窗只显示三种状态：**已关灯 / 还亮着 / 还没消息**。
- 不显示具体就寝时间、历史记录、目标时间；这些留在各自的「我的」。
- 不做排名、不做「谁最自律」、不显示谁先睡。
- 点开一张窗，只看到称呼、今晚状态、一个「给 TA 留盏灯」。解除关系收在底部。

### 关系动作

- 「邀请一个朋友」用微信分享，不要求对方先注册；
- 好友码、申请、备注收进折叠面板；
- 收到的申请叫「有人想和你一起」，不叫「好友申请」；
- 空状态：「一个人关灯，也成立。」

### 双人窗（P2）

在「一起」验证有人愿意用之后，再做双方确认的双人窗：

- 双方各自在自己的时间关灯；
- 只显示「已关灯 / 尚无记录」，不显示时间与连续；
- 解除后立即停止双向读取；
- 不做聊天、不做提醒轰炸。

## 留灯卡与回灯

### 触发时刻

1. 关灯完成后的 10 秒内（主入口，情绪最暖）；
2. 「一起」里的任意一扇窗；
3. 夜空里的「给下一个关灯的人留一句」后，可顺手留灯。

### 发送

- 三句预设文案，用户选一句，不开放自由输入；
- 卡面是同一扇暖窗，标题「给你留了盏灯」；
- 文案示例：
  - 「今天辛苦了，困了就去睡。不用回我。」
  - 「给你留了盏灯。你关不关，它都亮着。」
  - 「别撑了，我替你看着今晚。晚安。」
- 卡片链接只带不透明标识；不带发件人昵称、UID、就寝时间与历史。

### 接收

收卡人打开后，不是一张说明页，而是一个可以直接行动的场景：

```text
        有人给你留了盏灯

        「今天辛苦了，
          困了就去睡。不用回我。」

        来自一位今晚关灯的人

        [  我也关灯  ]   [ 回一盏灯 ]
             先收下，晚点再说
```

- 「我也关灯」：关闭卡片，进入自己的今晚；首次用户顺手完成时间设置；
- 「回一盏灯」：选一句预设，分享回给对方；不要求加好友，不要求回复文字；
- 「先收下」：直接离开，不产生任何社交压力；
- 过期或撤回后显示通用晚安，不再归因。

### 回灯的含义

v1 的「回灯」是一个动作，不是一条消息：收卡人分享一张新的留灯卡，原发送者不会收到「TA 回你了」的订阅通知。这样避免把轻仪式做成聊天软件，也避免订阅消息的打扰。

如果后续验证出强需求，再考虑「TA 回了一盏灯」的单向轻通知，每晚最多一条。

### 传播闭环

```text
完成关灯
   ↓
给 TA 留盏灯
   ↓
好友打开，读完晚安
   ↓
我也关灯 / 回一盏灯
   ↓
好友完成自己的第一次关灯
   ↓
再留给下一个人
```

这条链里没有「注册」，没有「加好友才能看」，也没有「必须回复」。传播的门槛越低，越可能真的发生。

## 视觉与动效

### 气质

不是「睡眠 App」，是「深夜房间里的一个物件」。

关键词：**旧窗、宋体、纸张、颗粒、单一暖光、留白**。

避免：紫色渐变、玻璃拟态、满屏光晕、emoji 堆叠、彩带、徽章、进度条式 KPI。

### 色彩

| 用途 | 色值 | 说明 |
| --- | --- | --- |
| 夜空底色 | `#080C18` | 接近黑，但不是纯黑 |
| 次级夜色 | `#111827` | 卡片、sheet |
| 暖光 | `#F2B36B` | 窗、主按钮、星 |
| 深暖光 | `#D98B43` | 窗玻璃暗部、按压 |
| 暖白 | `#F4EFE5` | 正文、标题 |
| 雾灰 | `rgba(244,239,229,.38)` | 次级文案 |
| 星白 | `#F6D49A` | 星点、晚安签 |

按时与较晚不用红绿区分。按时用亮星，较晚用淡星；仅此而已。

### 字体

- 标题、短句、数字：`Songti SC` / `STSong` / `SimSun`，有书页感。
- 正文、按钮、说明：`PingFang SC` / `Hiragino Sans GB`。
- 英文只作小号 editorial 标签：`LIGHTS OUT`、`NIGHT SKY`、`GOODNIGHT NOTE`，不承担信息。

### 窗

- 有窗框、窗台、玻璃反光、一点点水汽；
- 窗台上有植物和猫的剪影，作为「有人住在这里」的暗示；
- 亮窗是暖黄玻璃，暗窗是深蓝夜空 + 星；
- 关灯时玻璃从暖黄过渡到深蓝，不是简单地把一个 div 变黑；
- 首页、夜空、留灯卡、分享图使用同一扇窗，形成资产。

### 动效

- 按住：光随按压逐步收拢，轻微缩放；
- 熄灭：约 900ms，先暗一格，再整体暗下；
- 星光：暗下后 300–600ms 浮出，一颗流星只出现一次；
- 页面切换：淡入、轻微上移，不做弹跳；
- 默认静音；震动只在开始与完成两个点。

### 布局

- 自定义导航；顶部只留品牌和日期，右上角让位给微信胶囊；
- 主操作高度不小于 44px；
- 覆盖 320px 窄屏、长文案、放大字号；
- 底部 TabBar 四项：今晚 / 夜空 / 一起 / 我的；留灯卡不是 Tab，是落地页/浮层。

## 文案

### 语气

短、轻、具体，不解释，不训导。像一个人在关灯前说的话，不像一个 App 在运营用户。

- 不用感叹号；
- 不用「加油」「坚持」「自律」「打卡成功」；
- 不用「失败」「断签」「你已落后」；
- 不把用户当需要被纠正的人。

### 关灯短句

按夜晚轮换，同一晚稳定。示例：

- 今天就到这里。剩下的，明天再说。
- 把烦恼调成飞行模式。
- 你已经做得够多了，包括现在决定去睡。
- 被子是今晚最小的避难所。
- 今晚的月亮替你看完剩下的消息。
- 你不需要再证明什么了，睡吧。
- 关灯不是认输，是给明天留电。
- 今晚不卷，卷被子。
- 这一晚不需要完美，只需要结束。
- 如果今天很难，就先睡过去。
- 窗外的灯一盏盏灭了，你也该睡了。
- 晚安。明天见，或者不见，都没关系。

### 留灯卡文案

- 今天辛苦了，困了就去睡。不用回我。
- 给你留了盏灯。你关不关，它都亮着。
- 别撑了，我替你看着今晚。晚安。

### 微文案

- 按钮：`按住关灯` / `放下手机` / `给 TA 留盏灯` / `回一盏灯`
- 按压：`别松手…` / `就快好了…`
- 失败：`没关成，再试一次。`
- 完成：`灯灭了。` / `今晚不再打扰。`
- 空状态：`一个人关灯，也成立。`
- 夜空：`没有连续也没关系。回来关灯的这一晚，只属于这一晚。`

## 页面结构

| 页面 | 首屏 | 次级 |
| --- | --- | --- |
| 今晚 `/pages/home/index` | 一扇窗、一句状态、「按住关灯」 | 目标时间、七晚窗格、留灯 |
| 夜空 `/pages/nights/index`（新增） | 累计关灯的一句大字、七晚窗格 | 三十晚星图、数字、晚安签、投稿 |
| 一起 `/pages/friends/index` | 「今晚 N 扇窗和你一起暗下来」、好友窗格 | 邀请、申请、好友码、双人窗 |
| 我的 `/pages/profile/index` | 称呼、目标时间、好友码 | 夜空/一起入口、关于、提醒开关 |
| 留灯卡 `/pages/home/index?light=…` | 一盏灯、一句晚安、两个动作 | 首次时间设置、过期文案 |

保留现有路由，避免旧用户与旧分享链接失效。新增夜空页；「一起」沿用 `pages/friends`；「我的」沿用 `pages/profile`。

| 阶段 | 交付 | 进入下一阶段的条件 |
| --- | --- | --- |
| P0 仪式 | 今晚：亮窗、按住关灯、完成态、放下手机、七晚窗格；夜空第一版；我的重做；内置短句；留灯卡接收端（内测链接） | 10–15 人试用，至少 8 人能独立完成第一次关灯；能说出「关灯=准备睡」；完成到退出的中位数不超过 10 秒 |
| P1 留灯与一起 | 留灯卡发送端、卡片归因与过期；回灯；一起的窗景；邀请与申请；分享卡图；可选每晚订阅提醒 | 至少 30 张有效卡被打开；打开后 48 小时首次关灯率达到 30%；回灯率可观测；至少 5 对用户用满 3 晚 |
| P2 双人窗与晚安签 | 双方确认的双人窗；晚安签展示与投稿；举报/下架；提醒策略细化 | 双人窗带来复用；真实晚安签让完成态更有价值；隐私与审核边界通过测试 |

比例和人数是首轮内部决策线，不是对外承诺。原型阶段找理解和操作问题，小规模试用决定下一笔投入；比较时同时报告人数、比例和来源。

**P0 是否包含留灯卡？** 建议不包含发送端，但先做接收端页面与静态卡面。这样 P0 就能测试「收到卡的人会不会关灯」，不必等整条社交链完成。

## 成功指标

| 指标 | 口径 |
| --- | --- |
| 每周反复关灯的人 | 最近 7 个完整就寝周期里至少 3 个周期有服务端记录的用户数；分别报人数与比例 |
| 首晚激活 | 首次进入后 48 小时内完成一晚的用户占比 |
| 第二周复用 | 完整观察两周的首周激活用户，第 8–14 周期至少完成 3 晚的比例 |
| 收尾有多短 | 服务端确认到离开完成页/进入后台的时长；中位数目标 ≤10 秒；停留变长视为失败信号 |
| 留灯回流 | 每完成一晚产生的有效留灯卡数、卡片打开率、收卡人 48 小时首次关灯率、回灯率 |
| 关灯可靠性 | 去重后有效提交最终拿到记录的比例，目标 ≥99%；分列网络错误、重试恢复、周期切换 |
| 放下手机的实际帮助 | 试用者次日用一句话回顾「关灯后有没有放下手机」；可跳过；单独报告自述结果 |

只采集完成指标需要的事件、去重标识、版本、状态和来源。心语正文、昵称、具体就寝时间、联系人留在各自业务域。

**不把停留时长当成功指标。** 用户关灯后越快离开，说明仪式越完整。

## 技术兼容与最小实现

1. **保留数据。** 保留用户标识、目标时间、周期、打卡记录和统计摘要。夜空从已有记录派生；按时延续连续，较晚计入累计。
2. **保留路由。** `/pages/home`、`/pages/friends`、`/pages/profile` 继续存在，新增 `/pages/nights`。旧分享链接继续落到首页，读到 `light` 参数时展示留灯卡。
3. **关灯与心语解耦。** 打卡事务先完成并返回记录；晚安签查询失败不影响关灯。投稿从首页移出，放到夜空。
4. **仪式窗口在客户端。** 服务端窗口不改；客户端用目标前 3 小时/后 6 小时决定是否出现关灯动作。旧客户端仍可用原窗口。
5. **留灯卡最小实现。** P0 用预设文案 + 不透明短码 + 7 天有效期；落地页从短码取文案，不带发件人身份。生产环境用服务端短码/签名，不在链接里放 UID。
6. **回灯不带通知。** v1 的回灯只是分享回一张新卡，不新增消息系统；避免订阅消息和好友关系前置。
7. **一起只取最少字段。** 好友窗景只使用「今晚是否关灯」；不返回目标时间、历史、晚安签内容。解除关系立即停止读取。
8. **订阅提醒可选。** 我的页一个开关；每晚最多一条；默认关闭；文案只说「窗还亮着」，不制造焦虑。
9. **开关与回退。** 新首页、留灯卡、一起窗景分别用开关控制；新旧界面共用打卡与历史；回退后仍能读到新记录。
10. **验证。** `yarn verify`；微信模拟器 320px 窄屏；真机两个账号测试卡片、冷启动、热启动、过期、转发、弱网、重复点击、超时后重试、改目标、午夜与窗口边界。

## 风险与对策

| 风险 | 对策 |
| --- | --- |
| 「关灯」被误解为关掉手机/退出 | 首屏一句「准备休息时，来关一次灯」；完成态明确「今晚不再打扰」 |
| 长按不易发现 | 按钮写「按住关灯」；两次未按满出现轻点兜底；保留 44px 触控区 |
| 强制退出显得冒犯 | 「放下手机」是主按钮但不是唯一出口；旁边保留「看看夜空」 |
| 留灯卡变成社交压力 | 预设文案；「不用回我」；回灯是动作不是消息；不显示已读 |
| 统计重新制造焦虑 | 首屏零数字；夜空不出现红色/断签；连续只折叠展示 |
| 卡片被滥用 | 预设文案；短期有效；频率限制；不带 UID；过期降级为通用晚安 |
| 隐私泄露 | 卡片不带昵称、UID、时间、历史；一起只回当晚状态；解除即停 |
| 深色界面对比度不足 | 正文暖白、次级不低于 38% 透明度；真机检查；支持放大字号 |
| 只有单人使用，传播不成立 | 首批招募 5 对而非 10 个单人；把「发给一个具体的人」作为试用任务 |
| 订阅提醒变成打扰 | 默认关闭；每晚最多一条；完成关灯后当晚不再提醒 |

## 首轮验证

招募 5 对（情侣、室友、异地朋友）+ 10 位单人，完成以下任务：

1. 第一次打开，在 15 秒内设置时间并关灯；
2. 关灯后说出「这个产品想让我做什么」；
3. 把留灯卡发给一个具体的人，而不是发朋友圈；
4. 收卡人打开，完成自己的第一次关灯，或回一盏灯；
5. 连续使用 7 晚，第 8 晚不再提醒，观察是否自然回来。

访谈只问三件事：

- 哪一晚你觉得这个动作「真的结束了今天」？
- 你把灯留给了谁？为什么是 TA？
- 收到灯的那天，你关灯了吗？如果没有，是什么阻止了你？

首轮通过线：10 位单人里至少 8 位完成第一次关灯；至少 6 位能说出「关灯=准备睡」；至少 5 位愿意把灯发给一个具体的人；5 对里至少 4 对完成一次双向留灯；5 位收卡人里至少 3 位完成第一次关灯；第二周至少 30% 的人完成三晚。

## 需要拍板

1. **是否把「今晚关灯」作为正式品牌名**，替换「早睡助手」？建议是。代码仓库名可以继续叫 BedTime。
2. **是否接受「关灯后主按钮是放下手机」**？建议是。这是产品态度的核心，也是最有传播力的一句话。
3. **P0 是否先做留灯卡接收端**？建议是。发送端可以等 P1，但接收端是验证传播的最低成本方式。
4. **是否保留晚安签与投稿**？建议保留，但只放在完成态和夜空，不回到首屏。
5. **是否在 P1 加入每晚订阅提醒**？建议加，但默认关闭，且完成关灯后当晚不再提醒。

确认这五件事后，再做两件事：把「今晚」的关键界面做成可点击原型；用 5 对用户验证「关灯 → 留灯 → 回灯」这条链。先不铺开双人窗、排行榜、群房间和商业化。
