# 早睡助手产品重设计方案

2026 年 11 月 7 日 · 提案 v0.1

## 产品定位

**「今晚关灯」是工作名。** 用户已经想睡，却还在微信或短视频里多待一会儿。打开小程序，看见一扇亮窗，点一下关灯，收到一句晚安，然后放下手机。先把这个动作做成每晚愿意重复的仪式，再让用户把一张晚安卡送给在意的人。

首批面向两类用户。核心用户是「知道该收手机，但总想再看一会儿」的人。传播从已经会在微信里互道晚安的朋友、伴侣或异地亲友开始。两类用户可以重叠，个人使用从第一晚就能完整结束。关灯代表用户主动记录了准备休息的时刻，产品成效围绕这个行为衡量。

## 当前体验和重设计范围

| 现状 | 重设计 |
| --- | --- |
| 首页首屏突出日期和倒计时，往下依次是打卡、心语、投稿、统计和贴士 | 首屏只强调今晚的窗和当前能做的一件事。把记录、投稿和设置移到独立入口。 |
| 打卡成功主要是提示和有条件的心语弹窗，迟到还有额外的状态特效 | 关灯本身是完成反馈。晚一点同样有完整仪式，按时与较晚的区别留在个人记录。 |

| 按周期日保存打卡，支持跨午夜、重复请求和统计恢复 | 保留打卡与用户数据，围绕原生小程序重构页面、内容和分享入口。 |

## 每晚体验

**第一次打开。** 首页直接预览一扇窗，用一行字解释「准备休息时，来关一次灯」。默认建议 22:30，可接受或调整。昵称和好友邀请都可以稍后处理。已有用户直接使用自己的目标时间。

**准备休息。** 屏幕中央是一扇亮窗，底部是「今晚关灯」。窗口开启后即可记录。距离目标还很早时，首页先提示目标时间，关灯入口仍可见。过了目标时间，主按钮照常可用，辅助文案换成「晚一点，也可以把今天放下。」

**关灯完成。** 点击后按钮原位显示「正在关灯…」。服务端确认记录后，暖光在约 400ms 内收拢，窗外留下一点星光，页面显示一句晚安。示例「今天就到这里。剩下的，明天再说。」末尾提示「晚安，手机可以放下了。」同一晚重进直接看到完成态。记录未确认时留在原页，允许重试。

**第二天打开。** 首页在远离就寝时段时突出「昨晚」和「今晚目标」。进入「夜空」可以看到最近七晚，某一晚有记录就在对应窗格留一颗星。漏过的夜晚保持空白，打开当天仍从今晚开始。首版在回看中展示七晚记录次数和按时次数，长期累计与连续记录放在详情里。

### 首页状态与规则

| 场景 | 用户看到什么 | 行为 |
| --- | --- | --- |
| 尚未开窗 | 昨晚回顾、今晚目标和开放时间 | 可改目标、看回顾。 |
| 已开窗，离目标较早 | 今晚目标和亮窗，关灯入口低于目标提示 | 「提前关灯」可用。首轮原型用目标前 2 小时测试视觉切换，这只是展示分界。 |
| 接近目标或已经超过目标 | 亮窗与「今晚关灯」，晚一点也有同样的视觉反馈 | 一次点击提交。目标时刻及之前按时，超过目标记为较晚。 |
| 已记录 | 暗窗、一句晚安和收尾提示 | 重进恢复结果。晚安短句按周期稳定，同一晚刷新也能读回。 |
| 网络慢、失败或周期刚切换 | 原位等待或「还没确认，重新试一次」 | 重试先恢复已有记录。若周期已切换，刷新状态并让用户确认新周期。 |

首版沿用服务端窗口，目标前 12 小时开始，目标后 6 小时结束，结束时刻属于新周期的未开窗状态。例如目标 22:30 时，次日 04:29 仍属上一晚，04:30 起显示下一晚。目标 00:30 时，前一晚 23:30 已属对应的就寝周期。「昨晚」与七晚回顾按个人周期取数，跨午夜时仍能找回刚做完的记录。 [服务端时间规则](../cloudfunctions/common/time.js)

## 页面结构和视觉

| 页面 | 首屏与主要操作 | 次级内容 |
| --- | --- | --- |
| 今晚 | 一扇窗、一句状态、一个主操作。目标时间放在按钮附近 | 改时间与回看入口。完成态把导航弱化，让视线停在一句晚安上。 |
| 夜空 | 七格窗影与「过去七晚有 X 晚关灯」 | 展开单晚记录。现有累计、连续和个人设置从这里进入。 |
| 我的 | 关灯目标、称呼、动效偏好和账号入口 | 好友码、关系管理、隐私选项和自己的投稿记录下沉。 |
| 留灯卡 | 先完整显示一句晚安，再提供「设一个我的关灯时间」 | 独立落地页。已设置时间的用户可回到今晚页。 |

首页改造先保留现有路由入口，方便旧用户回到资料和好友关系。留灯卡经过验证后，再决定是否把「一起」放到一级导航。

```text
        今晚                        今晚已关灯
   目标 22:30

    ┌────────┐                     ┌────────┐
    │  暖窗  │                     │  暗窗  │  ·
    └────────┘                     └────────┘

    [ 今晚关灯 ]                   今天就到这里。
                                  剩下的，明天再说。

    改目标    看夜空                晚安，手机可以放下了。
```

- **色彩。** 夜间用深靛蓝 `#141A2C` 打底，暖琥珀 `#F5C47B` 只给亮窗和主按钮，正文用暖白 `#F4EFE5`。白天回顾可以用暖灰纸色。关灯后让画面变暗，文字保持可读。
- **图形。** 一扇简单的窗贯穿首页、七晚回顾和微信卡面。第一批画三态即可：亮窗、暗窗、带星点的暗窗。七格回顾用形状和文字标记记录状态，颜色作为辅助。
- **排版与反馈。** 移动端正文建议 16px，主要触控区至少 44px 高。首版动效只播放一次，默认静音，关闭动效时切换到静态暗窗。设计稿覆盖 320px 窄屏、长文案和放大字号，主操作在窄屏上也能直接触达。
- **内容。** 首轮准备 21 句可重复使用的原创短句，涵盖收尾、宽慰和日常幽默，标注「今晚关灯」。例如「今天先存个档，明天继续。」短句按周期轮换，始终有内置内容可以显示。

## 熟人传播

### 留灯卡

用户在准备页或白天回看里主动选择「给你留盏灯」，从三条文案中选一句，然后通过微信发给熟人。首个卡面用同一扇暖窗，标题「给你留了盏灯」，正文「今天辛苦了，困了就去睡。不用回我。」卡片本身就是一份完整的晚安。打开的人可以读完离开，也可以顺手设置自己的目标。

卡片链接只带不透明的标识，服务端返回预设文案，首轮暂定七天有效。过期或撤回后显示通用晚安，停止来源归因。卡面和落地页默认省略发件人昵称、UID、关灯时间及历史。转发只传播卡片内容。用户是否分享与心语、记录和使用权限分开。上线前在实际微信客户端核对转发卡面、冷启动、热启动、过期和被转发等场景，并按当前管理后台要求确认提审范围。

### 双人窗

留灯卡带来稳定回流后，再测试双方确认的双人窗。两扇窗分别代表自己和同伴，双方各自在自己的时间关灯。完成后可以直接离开，下一次打开再看对方的状态。双方授权时只显示相应晚间状态「已关灯」或「尚无记录」。各自的目标时间、是否按时与历史记录留在个人页。解除后立即停止双向读取。涉及两个目标周期时，页面明确标示「今晚」的共同展示日期，每个人的写入和统计仍按自己的周期。首轮先测同一时区、目标跨午夜的组合。

### 第一轮运营

单人封测招募 30–50 位有睡前刷手机习惯的人。招募物料只展示一个可复现的动作，例如 8 秒的亮窗、点按、熄灯。第二周保留产品入口，撤掉研究组织者的主动提醒，观察用户是否还会回来。留灯卡上线后，优先邀请已有晚安习惯的朋友或伴侣试用，观察他们是否会自发发给下一位熟人。群房间、订阅提醒和商业化等到个人复用与一对一传播各有证据后再排期。

## 版本范围与验收

| 阶段 | 交付 | 进入下一阶段的条件 |
| --- | --- | --- |
| 原型 | 首开、设置时间、亮窗、完成态、七晚回顾、微信卡面和接收页 | 约 10 人执行任务，至少 8 人能独立完成首次设置和关灯，并能正确说出关灯记录的含义。能看出晚点仍可关灯、收卡无需回礼。 |
| P0 单人关灯 | 重做今晚和夜空，使用编辑短句，保留目标和历史，加入最小统计 | 首轮两周封闭体验，第二周至少 30% 的首周激活者完成三晚。写入成功率和完成页停留达到下文目标，访谈有人能具体描述何时愿意再次关灯。 |
| P1 留灯卡 | 聊天卡片、独立落地、归因与过期处理 | 累计至少 30 位新访客从有效卡片打开，48 小时首晚转化达到 20% 的试验目标，并有跨两周重复发卡的用户。样本不足时延长观察。 |
| P2 双人窗与心语试验 | 先小范围试双人窗。用户投稿的展示单列实验，准备审核、举报和下架能力 | 分别验证双人窗是否带来复用、真实来信是否让收尾更有价值。通过后再扩大。 |

比例和人数是首轮内部决策线。原型结果用于找理解和操作问题，小规模试用用于决定下一笔投入，比较时同时报告人数、比例和招募来源。若首晚容易完成但第二周复用低，先找出用户在什么时刻想得起这个动作。若卡片有真实打开却很少有人关灯，优先检查接收页和首次设置的衔接。

## 成功指标

| 指标 | 口径与用途 |
| --- | --- |
| 每周反复关灯的人数 | 最近七个完整的个人就寝周期里，至少三个周期有服务端确认记录的独立用户数。相同用户和周期只计一次，按时与较晚均计入。同步看同口径比例，区分新增与复用。 |
| 首晚激活与第二周复用 | 首次进入后 48 小时内完成一晚的人数占比。对完整观察满两周的首周激活用户，统计第 8–14 个周期至少完成三晚的比例。 |
| 收尾有多短 | 从服务端确认并显示完成态到离开该页或小程序进入后台，记录中位数和 90 分位。首轮中位数目标不超过 10 秒，同时检查过快退出是否来自失败或误操作。页面事件用来估计体验时长。 |
| 关灯可靠性 | 按用户和周期合并重复操作，统计窗口内有效提交最终拿到记录的比例。目标至少 99%，同时分别看网络错误、重试恢复和周期切换。封闭期同时报告实际失败次数。 |
| 留灯回流 | 分开看发起分享的人、去重后的有效落地访客、其中 48 小时内完成首次记录的新用户。发起分享只代表调起操作。重复打开去重，现有用户回访另列。 |
| 放下手机的实际帮助 | 试用者在次日用一句话回顾「关灯后有没有放下手机」「哪一晚这个动作有帮助」。可选 3 晚试用前记录和 7 晚试用记录作对照，单独报告自述结果。 |

只采集完成指标需要的事件、用户去重标识、版本、状态分类和来源。心语正文、昵称、具体就寝时间和联系人信息留在各自的业务域。试用者可跳过次日反馈。

## 数据兼容和上线验收

1. **保留已有记录。** 保留用户标识、目标时间、打卡周期和事务统计。七格夜空从已有打卡派生。按时延续连续，较晚计入累计。近期最佳继续按已有记录范围展示。先拆开首页的今日状态和历史加载，历史失败时仍可进行当晚操作。 [共享状态](../miniprogram/state/create-app-store.ts) · [统计定义](checkin-and-friends-backend.md)
2. **把心语移出关灯关键路径。** 现有提交先抽取心语，再进入打卡事务，查询故障会影响关灯。P0 新入口复用同一打卡事务，独立于心语池完成写入，再用内置晚安收尾。旧投稿和已关联的奖励保存原归属。投稿入口从新版首页移出，受保护的历史入口保留。将来向他人展示投稿时，先处理能从现有心语 ID 推回作者 UID 的问题，使用最少返回字段，并加入举报和撤回后的失效处理。投稿成功与领取心语继续分别处理。 [提交逻辑](../cloudfunctions/common/checkins.js) · [心语返回结构](../cloudfunctions/common/goodnight.js)
3. **按场景拆分授权。** 留灯卡、好友关系和可见状态是三件事。上线双人窗前改造服务端返回范围，按双方授权只返回需要的当晚状态。过期、撤回、非成员访问和旧客户端都要纳入测试。 [好友查询逻辑](../cloudfunctions/common/friends.js)
4. **分步切换。** 新旧界面在小流量阶段共用打卡和历史。用开关分别控制新首页和留灯入口。回退界面时仍能读到新界面记录的打卡。改代码后完成仓库验证和微信模拟器窄屏验收。真机用两个账号验证卡片、权限与重进恢复，补测弱网、重复点击、超时成功后重试、改目标、午夜以及窗口关闭边界。

## 进入原型的决策

先拍板三件事。是否把「关灯」定为核心动作，是否采用暖窗作为视觉记忆点，是否同意首版只验证单人仪式。确认后制作今晚的亮窗和暗窗、七晚回顾、留灯卡和接收页，连成两条可点流程。先看用户如何完成第一晚，再决定首页要删、要留和要下沉的内容。
